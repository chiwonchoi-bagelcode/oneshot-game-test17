# Splash Rescue (물총 구조대) — audio report

All audio is generated by code. The only third-party sound source is the MIT-licensed FluidR3 GM soundfont (`/usr/share/sounds/sf2/FluidR3_GM.sf2`); no other samples are used.

```
python3 audio/src/build_all.py              # rebuild everything (~2.5 min on 4 cores)
python3 audio/src/build_all.py --music      # or --stingers / --sfx / --analyze ; --keep-wav keeps audio/build/
```

The build is deterministic (crc32-seeded RNGs; FluidSynth, pedalboard and LAME are deterministic). Two clean builds in a row produced byte-identical `audio/out/*` (md5 on all 55 files).

| folder | contents |
|---|---|

## 1. Music

**How it is made.** Chords are written as symbols (`"F | C/E | Dm7 | F/C"`), melodies in a compact note language whose parser checks bar lines. Helpers generate strums (per-string delay, up/down strokes), voice-led arpeggios, bass lines with approach notes, drum grids with phrase-end fills, CC11 swells and delayed vibrato. Humanisation: 3–8 ms timing jitter per track, velocity jitter, metric accents, light swing — all seeded. Each track is rendered to its own stem with FluidSynth (its reverb/chorus off), then EQ'd and levelled relative to the lead. Mix bus: synthetic stereo hall (RT60 1.3–2.2 s), filtered ping-pong delay on the lead, gentle tilt EQ, 1.8:1 glue compressor, safety limiter. Loudness is corrected on the *decoded* MP3 until it reads −18.0 LUFS.

**Seamless loops by construction.** Note onsets wrap modulo the loop length; each stem is rendered with 5–6 s of extra tail which is folded back onto the loop start (exactly what the 2nd+ pass of a loop sounds like); reverb is a circular FFT convolution; every stateful stage (filters, compressor, limiter) is pre-fed the loop end so its state at sample 0 matches the last sample; loop lengths are exact sample counts.

## 2. SFX (mono, 44.1 kHz, CBR 96 kbps)

- **Water**: `spray_loop` is exactly 2.000 s and built circularly (stream-shaped noise, loop-periodic wobble, low gurgle, 95 bubbles whose tails wrap). Bubbles follow van den Doel's rising-pitch damped sine. Splashes = band-pass-swept noise + bubble clouds + a soft "plop".
- **Jelly and enemies**: pitch-gliding sines with wobble, low-passed squelches; voices (spit, "oof", chirps, boss roar) use formant-filtered harmonic sources. Everything here is low-passed at 2.5–4.5 kHz so nothing sounds gross or harsh.
- **Rewards**: synthesized bells and coin partials plus FluidSynth celesta/glockenspiel/harp/vibes/marimba; sparkles use only C-major pentatonic notes. `rescue` = harp glissando → bell chord → sparkle shower → two happy chirps.
- **Finishing**: 25 Hz high-pass, leading silence ≤ 2.5 ms, −60 dB tail trim, 3 ms fade-in / ≥10 ms fade-out, click detector finds 0 clicks in all 45 files.
- **Levels**: smaller of a peak cap and a loudness target per tier (frequent ticks −22…−24, gameplay −13.5…−16.5, rewards −12…−13.5, measured as loudest 100 ms K-weighted window), so normal SFX sit 3–6 LU above the −18 LUFS music.

## 3. Loop-seam verification

1. By construction (above).
2. Exact decoded length equals `samples` in the manifest (LAME header carries delay/padding).
3. Seam step ratio |x[0] − x[−1]| ÷ 99.9th-percentile step: 0.02–0.27 for music, 0.16 for spray_loop (a click would be ≫ 1).
4. High-frequency energy at the seam ranks at the 29th–71st percentile against other bar downbeats (a click would rank near 100).
5. `review/spray_loop_x2_seam.png` shows no visible discontinuity.

## 6. Limitations

- Nobody listened to these: all judgments come from measurements, spectrograms, piano rolls and the harmony checker. Weakest GM patches are likely harmonica, whistle, steel drums and accordion.
- Older Safari `decodeAudioData` may not trim the MP3 encoder delay (1105 samples). The game streams music through `<audio loop>`, so a tiny loop gap is possible there; shipping an Opus/OGG copy would be the robust fix.
- In the game build, stingers (manifest `music` entries with `"loop": false`) are embedded with the SFX so they play instantly.
